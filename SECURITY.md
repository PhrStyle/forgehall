# Security

## Threat model in brief

Forgehall starts AI agents that can read and write files and, if you allow it, run commands. Assume an agent can be wrong, and can be manipulated by text it reads.

- **Agents run commands and edit files.** Assume an agent can be wrong or be manipulated by text it reads. Forgehall limits what a wrong agent can do with several layers, none trusted alone; the full picture is in [Isolation and permissions](docs/concepts/isolation-and-permissions.md).
- **Isolation by default.** Each agent runs in its own Docker container as a non-root user, with its own work volume ([guide](docs/guides/run-agents-in-docker.md)). Runners report a mode (`container`, `vm`, `host`). The bus refuses `host` runners (`403`, and the runner exits) unless you turn on "Allow agents directly on this machine" in Settings; even then host runs get no standing permissions and every tool use is asked. **Caveat:** the mode is self-reported by the runner. It prevents accidental host runs, not a determined local user. Containers share your kernel, so a container escape is not covered; Incus VMs with network allowlists are planned (phase 5), and today an agent's container can reach the network.
- **Tool permissions.** Defaults for isolated agents allow file tools and test, build and inspect commands, ask before package installs, network access (`curl`, `wget`, `WebFetch`, `WebSearch`) and recursive `rm`, and deny `sudo`, `su` and reading secrets (`.env`, keys, `~/.ssh`, `~/.claude`). Anything not allowed or denied becomes a **permission request** that waits for you in the console; unanswered requests are denied after 15 minutes and the agent is told not to retry. "Always allow" adds a rule to that agent, so review what you approve: a broad rule such as `Bash(npm install *)` runs install scripts from any package. These rules are enforced by Claude Code itself; they reduce risk and do not remove it.
- **Admin token.** Everything under `/api` (approvals, permission answers, settings, creating tasks and repositories) requires `~/.forgehall/admin-token`, created with mode `0600`. Anyone who can read it can act as you: keep it out of the repository and shell history. The console's dev server adds it server-side and it never reaches the browser bundle. Agents share a Docker network with the bus but do not hold it; a call to `/api` from that network gets `401` (verified). Agents authenticate only on `/mcp`, `/runner` and `/git` with their own tokens, scoped to their workspace.
- **Secrets passed to containers.** The agent token and the Claude token (`CLAUDE_CODE_OAUTH_TOKEN`) reach the container as environment variables, so anyone who can run `docker inspect` (or read the container's environment) on this machine can read them. Treat the machine's Docker access as trusted. The agent token only opens that agent's bus access; the Claude token acts as your login. `fh agent token` or `fh agent run` rotates the agent token.
- **Tokens stay local.** Each agent has a bearer token; only its SHA-256 hash is stored in Postgres, and it is printed once by `fh agent token`. Claude credentials never go to the bus. Forgehall does not broker or share subscription credentials, and should only be used with your own accounts. A `claude setup-token` token is valid for a year and acts as your login: keep it in a file only you can read (`~/.config/forgehall/claude-token`, mode `0600`), never in the repository or shell history. The runner sends each prompt through stdin and the MCP config (with the agent token) through a temporary file readable only by its user, so neither appears in the process list.
- **Network exposure.** The stack publishes the bus on `127.0.0.1:4545` and Postgres on `127.0.0.1:5433` only, and speaks plain HTTP. Do not publish them on a public interface; there is no TLS yet. Postgres uses a development password. The bus listens on all interfaces inside its container so that agents can reach it on the `forgehall-agents` network; that network is not published outside Docker.
- **Prompt injection between agents.** An agent that reads untrusted content (web pages, issue text, files) can be tricked into asking another agent to do something harmful. Current mitigations: messages from other agents are framed as data and not as user instructions; `accepts_from` can restrict who may send `request` to an agent; workspace-scoped tools keep damage inside one workspace; and runs have limited tool permissions with the rest asked to you. Planned: stricter per-type policies, credentials that cannot merge or push to protected branches, and human approval for merges and memory changes. These reduce risk but do not remove it; do not give an agent that reads untrusted input the power to do irreversible things.
- **Supply chain.** The runner image pins the Claude Code CLI version (`CLAUDE_CODE_VERSION` in `infra/docker/Dockerfile`). Update it deliberately and rebuild the image.

## Reporting a vulnerability

Please do not open a public issue. Open a private security advisory on GitHub for this repository (placeholder: the exact link will be added when the repository is published). Include steps to reproduce, the affected version or commit and the impact you expect. You will get an acknowledgement as soon as the maintainer can respond; this is a small project, so please allow some days.

## Supported versions

Only the latest commit on `main`. There are no releases yet.
